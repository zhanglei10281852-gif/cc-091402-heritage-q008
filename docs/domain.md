# 保护业务约定

服务面向博物馆的藏品、修复和公共服务场景。时间字段统一使用带时区的 ISO 8601 字符串，身份字段使用不可变字符串。后续模块应在保存业务变更时保留经办角色和发生时间，避免用展示层文本代替结构化状态。

健康检查只用于确认进程存活，不代表任何业务流程已经完成。数据文件若需要落盘，应放在运行时配置指定的位置，测试不得依赖主机上的隐藏状态。

## 灾害响应模块约定（src/domain.js）

- 所有状态变更都是事件：命令先做全部业务校验，再通过 `EventStore` 追加事件（JSONL、逐条 fsync）并投影；状态只能由 `project()` 改变，重启靠重放恢复，不存在第二条写入路径。
- 事件同时记录 `occurredAt`（业务发生时间，可由现场补报提供）和 `recordedAt`（落盘接收时间）。时间线展示按 `occurredAt` 排序，`seq` 保留真实接收顺序以便审计。
- 现场上报只追加、不覆盖：同房间的矛盾电话记录全部保留在 `evidence` 中，当前状态按发生时间最新者裁定，被推翻的旧报标记 `contradictsCurrent`。
- 资源可用量、人员班次的冲突检测跨所有并行事件全局进行；封锁是全局硬状态，普通调度（含普通路线）一律不得覆盖，紧急通行必须留下批准人与失效时间。
- 转移批次以逐件签收为完成前提；负责人出发时刻必须存在被签到覆盖的有效排班。
